# 내장 브라우저 운영

검색 페이지·PDF 웹 표시·편집기 UI는 Codex 내장 브라우저를 사용한다. 사용자가 다른 브라우저를 명시적으로 지정한 경우에만 그 선택을 따른다. 내장 브라우저 실패를 외부 Chrome/Edge 자동 전환으로 해결하지 않는다. 이 정책은 Codex 도구 실행 지침이며 외부 브라우저의 설치·설정이나 도구 런타임 자체를 변경하지 않는다.

## 연결 확인

1. 현재 브라우저 도구 인벤토리에서 `type: iab`와 실제 탭 ID를 확인한다. 기존 대상 URL의 탭을 재사용한다. 새 탭이 필요하면 현재 도구가 지원하는 `cua.createBrowserTab('iab', url, {visible:true})` 등 내장 브라우저 명시 API를 사용한다. URL만으로 브라우저를 자동 선택하는 호출을 피한다.
2. 제목·대상 문서 ID·본문과 로그인 상태를 읽어 확인한다. 마스터의 브라우저 ID나 핸들이 서브에이전트에서도 같다고 가정하지 않는다.
3. 편집 담당은 자기 세션에서 내장 브라우저 접근을 읽기 전용으로 한 번 확인한다. 목록에 없거나 unavailable이면 반복 시도·외부 브라우저 생성 없이 마스터에 보고한다.
4. 새 로그인이 필요하면 마스터가 connector의 `open --print-url`로 일회용 handoff URL을 발급하고 즉시 내장 브라우저에 연다. URL·키는 기록/메시지에 저장하지 않는다. 기존 내장 로그인은 재사용한다. 인자 없는 `open`은 OS 기본 브라우저를 여므로 자동화 실행에 사용하지 않는다.

## 편집 역할 결정

- 편집 담당의 내장 접근이 확인되면 마스터는 조작을 중지하고 기존 단일 편집 인계를 수행한다.
- 편집 담당의 내장 접근이 불가하고 마스터는 가능하면 **마스터가 편집 역할을 겸임**한다. 추출 담당은 로컬 원본 이미지를 독립 열람한다. 기존 편집 담당은 UI 조작을 중지하며 필요하면 읽기 전용 초안·증거 검토만 맡긴다.
- 겸임 시에도 공식 claim의 문서 ID·토큰·버전·해시 확인 → UI 입력 → 저장·재열람·원본 대조 → 증거 작성 → submit → finish/return 순서를 유지한다. 상태 검증을 우회하지 않는다. 동일 담당의 자기 검증임을 기록하며 독립 편집 담당 검증이나 검토/편집 동시 수행으로 보고하지 않는다.
- 겸임 중 불필요한 편집 중계 서버를 시작하지 않는다. 기존 서버가 있다면 현재 항목 인계가 끝나고 중지됐음을 확인한 뒤 수동 상태 전환으로 이어간다. 실제 editor_agent는 마스터로 기록하고 마스터의 모델을 편집 권장 Astra로 허위 표기하지 않는다.
- 마스터도 내장 브라우저에 접근할 수 없으면 준비 자료·기존 ID·재개 위치를 보존하고 UI 작업 불가를 보고한다. 외부 브라우저 사용을 기정사실화하지 않는다.

실행 기록에 browser_policy=`iab`, browser_type, 실제 browser_id/tab_id, editor_agent, editor_mode=`dedicated` 또는 `master`, 접근 확인 결과를 남긴다. 기존 실행의 browser 기록을 소급 변경하지 않는다.

## 확인 범위

현재 환경의 재확인에서는 마스터의 내장 문서 열람·메뉴 열기/닫기가 성공했고, 편집 서브에이전트에는 내장 브라우저가 노출되지 않았다. 이는 모든 환경에서의 고정 제한이 아니다. 후속 빠른 검증에서 마스터가 내장 브라우저로 일반 문서 생성 → 한글 텍스트·PNG 포함 HTML 클립보드 붙여넣기 → 저장됨 확인 → 같은 ID 재열람을 수행했고 텍스트 보존과 이미지 로드를 확인했다. OS 파일 선택기를 통한 업로드와 모든 문항 형식의 호환성은 별도 검증 대상이다. 과거 Chrome 검증을 내장 검증으로 합산하지 않는다.
