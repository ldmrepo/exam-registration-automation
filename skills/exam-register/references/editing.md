# 단일 편집 에이전트 절차

[편집 역할](roles/editor.md)과 [편집 기능 지침](editor-playbook.md)을 읽는다. 편집기 제어권은 이 담당자 하나에만 있다. 추출 결과의 의미·정답을 재해석하지 않는다.

## 수령과 입력

1. 마스터의 `EDIT` 배정 메시지와 현재 공식 기록에서 항목 ID·대상 문서 ID·명세 버전·초안 버전·배정 토큰이 모두 같은지 확인한다. 토큰이 취소됐거나 문서 유형이 다르면 입력하지 않고 반환한다.
2. 해당 문서 ID를 직접 열고 실제 제목·유형·현재 본문을 확인한다. 빈 문서라는 기록만 믿고 전체 선택으로 기존 사용자 내용을 지우지 않는다. 예상과 다르면 현재 상태를 마스터에게 보고한다.
3. 확정 초안의 텍스트·수식을 편집 가능한 요소로 입력하고 원본 그림을 삽입한다. 현재 화면에서 확인한 UI·키보드·클립보드만 사용한다. 좌표/선택자를 과거 실행에서 그대로 재사용하지 않는다.
4. 원본에 맞춰 박스 헤더, 이미지 비율·정렬·간격, 답항 순서·열 수, 표·문자표를 조정한다. 의미를 보존하는 서식 조정만 수행한다.
5. 공식 정답과 배점을 입력하고 실제 저장 표시를 확인한다. 이어서 [재열람 검증](verification.md)을 수행한다.

준비 완료 순서는 마스터 대기열이 결정한다. 편집 담당은 임의로 다음 문서를 선택하거나 새 문서·폴더를 생성하지 않는다. 현재 항목 검증/반환을 보고한 뒤 다음 배정을 받는다.

마스터가 제공한 `preview-next` 자료는 다음 항목의 로컬 파일 열람과 붙여넣기 템플릿 준비에만 사용한다. 원본·초안 파일을 수정하지 않는다. preview는 토큰·소유권을 부여하지 않으며 실제 EDIT 토큰 수신 전에는 다음 문서로 브라우저를 전환하거나 쓰기를 수행하지 않는다. 실제 배정의 ID·버전·해시가 preview와 같을 때만 미리 준비한 내용을 사용한다.

재열람·원본 대조 증거를 작성한 즉시 짧은 VERIFIED(항목·문서 ID, 버전·토큰, 증거 경로, 미해결 없음, 브라우저 조작 중지)를 마스터에게 보낸다. 마스터는 submit-and-claim의 새 토큰과 경로를 짧은 EDIT로 전달하고 이전 항목의 시각 심사를 후속으로 병행한다. 편집 담당은 새 배정 확인 후에만 다음 문서를 열며 이전 증거와 스크린샷을 보존한다. manifest·대기열·공식 CLI의 소유권은 계속 마스터에게 있다.

## 실패와 인계

증거 JSON은 `python scripts/evidence_writer.py --run <run> --item <현재 ID> --token <현재 edit_token> --payload <임시 JSON 경로 또는 ->`로 저장한다. `-`는 stdin JSON을 받는다. 이 도구는 manifest를 읽기만 하며 현재 editing 대상·문서 ID·version·토큰을 확인한 뒤 `verification/<현재 ID>/evidence.json`을 새로 만든다. screenshot은 같은 항목 디렉터리 안의 기존 파일이어야 한다. payload의 document_id/version은 필수이고 id/edit_token이 있으면 현재 배정과 일치해야 한다. 현재 editing 확인은 제출·심사 검증을 대신하지 않는다.

이미 evidence.json이 있으면 덮어쓰지 않고 중단한다. 이전 제출·완료 증거는 불변이며 새 시도는 마스터에게 인계해 별도 증거 경로를 조정한다. 파일을 지우거나 다른 항목 디렉터리로 우회하지 않는다. CUA 세션에서 만든 증거 payload는 파일 작성 호출마다 현재 run·item·문서 ID·version·token을 명시해서 구성한다. 이전 문항 값을 캡처한 전역 변수나 closure를 재사용하지 않는다. 반환된 evidence 경로와 현재 배정 ID를 확인한 뒤 VERIFIED에 그대로 전달한다.

붙여넣기·배열·저장 오류는 같은 문서에서 수정하고 재검증한다. 잘못 삭제했으면 Undo/Redo 후 실제 내용을 확인한다. 저장이 불명확하면 새 문서를 만들지 않고 기존 ID를 재열람한다.

판독·정답·그림 누락은 `NEEDS_REVISION`으로 마스터에게 반환한다. 초안 파일을 고치거나 답을 추정해 입력하지 않는다. 문서 ID/유형/좌표 오류는 마스터 책임으로 반환한다. 편집기 기능·인증 장애는 현재 URL·저장 단계·오류와 재개 조작을 기록하고 마스터에게 보고한다.

검증 증거는 `verification/<item_id>/`에 작성한다. `EDITED`는 입력·저장 단계 보고일 뿐 완료가 아니다. 재열람·원본 대조가 모두 통과하면 `VERIFIED`에 문서 ID·사용 버전·배정 토큰·증거 경로를 포함해 제출한다. 공식 상태와 대기열은 마스터가 변경한다.


## 고정 입력 게이트 (재측정 전 준비 완료)

1. 실제 URL·제목·현재 본문을 배정과 대조한다. 예상 밖 사용자 변경은 덮어쓰지 않는다.
2. 현재 화면에서 본문 편집 locator를 관찰하고 클릭한다. read-only DOM/접근성 관찰로 초점이 실제 본문 편집 영역 안에 있음을 확인한 후 해당 locator에 선택·붙여넣기 키를 보낸다. 툴바·사이드바·정답 필드 초점이면 다시 맞춘다.
3. 붙여넣기 후 번호·문단·native 수식·박스·단답 입력 구조·정답을 확인한다. 단답형은 interaction 1개, 불필요한 빈 prompt 0개, rows 1이다. 불완전하면 저장하지 말고 Undo로 직전 상태를 확인한 후 한 번 복구한다. 반복 무반응이면 같은 ID 재열람으로 초점을 복구하며 무작정 Backspace를 반복하지 않는다.
4. 저장 표시 확인 후 같은 ID를 다시 열어 원문과 구조·정답이 유지되는지 확인한다.
5. evidence_writer에 input_checks의 target_confirmed, main_editor_focus_confirmed, structure_before_save_confirmed, structure_after_reopen_confirmed를 실제 관찰 후 true로 제출한다. 누락/false면 파일 생성이 거부된다. 이 플래그는 브라우저 관찰을 자동 수행하지 않으며 마스터 시각 심사를 대신하지 않는다.

모델·effort·초안·입력 템플릿·저장 도구·인계 도구 준비와 점검을 끝낸 후 측정을 시작한다. 실행 중 도구 교체가 필요하면 해당 시도를 별도 표시하고 정상 측정과 섞지 않는다. 모든 문항에 같은 재입력→저장→재열람 기준을 적용하고 오류 시간을 제외하지 않는다.


마스터가 제한 시간 중계기를 시작한 실행에서는 [자동 인계 절차](handoff-relay.md)를 따른다. 편집 담당은 증거·요청을 제출하고 반환된 새 토큰을 확인하며, 공식 상태 변경은 마스터 소유 중계기만 수행한다. 마스터 시각 승인과 finish는 그대로 유지한다.


## 호출 묶기와 상태 기반 대기

선택형은 정답 번호뿐 아니라 단일/복수 선택 모드도 명시적으로 확인한다. 편집 화면의 체크박스 모양은 모드를 증명하지 않는다. 현재 컨텍스트 메뉴에서 단일 선택으로 전환하고, 저장·재열람 후 메뉴가 `복수 선택으로 변경`을 제공하는지 등 실제 설정 근거를 확인한다.

사용자 확정 배치 규칙: 원본이 `발문 → 답항 → 그림` 순서인 유형은 편집기에서 후행 그림 배치를 지원하지 않으므로 그림을 발문 영역 하단에 삽입한다. 등록 순서는 `발문 → 그림 → 답항`이다. 그림의 내용·비율을 보존하고 가운데 정렬하며 불필요한 발문-그림 간격을 제거한다. 이 배치 변경은 승인된 변환으로 기록하며 원본 순서 차이만으로 보완 대기로 반환하지 않는다. 문항 번호·시험지 식별은 배치 규칙과 별도로 원본에서 확인한다.

- 사전 준비한 항목별 텍스트·수식·그림 payload를 사용한다. 현재 UI에서 확인한 locator에 한해 초점 확인→선택→붙여넣기 등 지원된 순차 조작을 한 도구 호출 안에 묶을 수 있다. 서로 다른 문서의 UI 쓰기를 병렬로 실행하지 않는다.
- 붙여넣기 뒤 구조 관찰은 생략하지 않는다. 정답 설정과 저장은 구조가 정상임을 확인한 뒤 수행한다. 구조 오류를 숨기거나 저장 성공을 추정하는 일괄 호출은 금지한다.
- 고정 sleep을 저장 완료의 근거로 쓰지 않는다. 현재 도구가 문서화한 조건 대기/locator 기능으로 실제 저장 상태·본문 번호를 확인한다. 지원되지 않는 wait API를 만들지 말고 필요한 상태만 제한적으로 다시 읽는다.
- 재열람·원본 대조 후 같은 지원된 CUA 호출에서 screenshot 저장과 명시적 항목 payload 작성을 마친다. 다음 relay request 호출에서 증거 저장·요청·대기를 수행한다. 증거 작성용 추가 셸 호출은 필요하지 않다.
- 새 인계 응답의 ID·버전·토큰·해시를 사전 준비 명세 및 현재 공식 상태와 확인한다. 이미 고정해 읽은 원본/초안 전체를 매번 출력하지 않는다. 오류·새 버전·해시 변화가 있으면 사전 준비를 무효화한다.
