# 편집 기능별 조작과 복구

2026-09-09 관찰에 근거한다. UI 이름·DOM 선택자는 현재 화면에서 확인 후 사용한다. 예전 AX 번호·탭 ID·마우스 좌표를 재사용하지 않는다.

## 공통 조작

- 실제 편집 본문은 관찰 당시 `.ProseMirror[role="textbox"]`다. 왼쪽 목록 미리보기에도 `.ProseMirror`가 있으므로 전체 문서에서 찾지 않는다.
- 답항은 해당 `[data-qti-type="qti-simple-choice"]` 내부, 표는 해당 셀로 범위를 제한한다. 문단 추가 후 기존 전역 순번을 그대로 쓰지 않는다.
- 내용·서식 변경은 UI·키보드·허용된 붙여넣기로 수행한다. DOM 읽기는 내용·선택 위치·스타일·크기 검증용이다. DOM/앱 상태를 직접 변경하지 않는다.
- 잘못 삽입·삭제하면 Undo, 되돌린 조작을 재적용할 때 Redo를 사용한다. 복원된 내용과 커서 위치를 확인하고 계속한다.

## 지문과 보기박스

지문 안내 `[1～3] …`는 밖에 두고 기본 보기박스를 삽입한다. 지문 박스만 우클릭 → 라벨 입력 → 빈 값 → Enter로 헤더를 없앤다. 관찰상 `setValue('')` 후 Enter는 적용됐고 일부 `fill('')` 시도는 헤더가 남았다. 헤더가 실제 사라졌는지 확인한다. 문항의 `<보기>`, `<자료>` 헤더는 원본대로 유지한다.

단이 넘어가는 [44~45]는 왼쪽 `(가)` 전체 → 오른쪽 `(나)` 순서로 같은 일반 문서·같은 박스에 입력했다. 화상 회의 이미지가 대화 중간에 있었으므로 대화 4번 뒤에 두고, 기사 이미지는 `(나)` 다음 독립 문단에 뒀다. 페이지 경계도 원문의 연속성으로 판단하되 실제 페이지 경계 입력은 추가 검증 대상이다.


## 발문·수식·답항

- 수식은 커서 지정 → 수식 도구 → LaTeX 입력 → 추가로 넣고 렌더를 원본과 대조한다. PDF 문자열의 이스케이프나 줄바꿈을 그대로 믿지 않는다.
- 답항은 원문 번호 순으로 입력한다. 부족한 보기는 `추가하기`로 생성하며 해당 답항의 체크박스로 정답을 지정한다. 메타데이터·정답은 목록 썸네일 대신 실제 본문에서 확인한다.
- 과거 검증한 수학 7·14번은 가로 5단, 긴 국어 답항은 원문처럼 1단을 사용했다. 모든 과목·문항에 5단을 강제하지 않는다.
- 답항 안의 복수 줄은 개별 답항 안에서 문단을 나누고 보기 수가 늘어나지 않았는지 확인한다.


## 이미지

1. 시각 확인한 원본의 해당 그림을 PNG로 확보한다. 축·점·기호·주석이 잘리지 않았는지 확인한다. 도형을 임의로 재생성하지 않는다.
2. 본문에 커서를 두고 이미지 포함 HTML을 붙여넣는다. 사용 가능한 CUA 문서에 해당 API가 있을 때의 예: `tab.paste('<p><img src="data:image/png;base64,..." width="..." height="..." alt="..."></p>', {format:'html'})`.
3. PNG만 클립보드에 기록한 뒤 붙여넣기는 이 세션에서 삽입되지 않았다. HTML 방식은 수학 14번과 국어 [44~45]에서 성공했다.
4. 크기 메뉴의 비율 고정으로 읽을 수 있는 폭을 적용한다. 원본 비율·편집기 폭을 보고 결정하며 과거의 360px·560px를 고정값으로 쓰지 않는다.
5. 이미지 레이아웃의 가운데 정렬 또는 독립 이미지 문단의 문단 정렬 → 중간 정렬을 적용한다. HTML의 정렬 스타일이 유지된다고 가정하지 않는다.
6. 발문과 그림 사이 불필요한 빈 문단을 제거한다. `(나)`와 이미지가 한 문단에 붙으면 표제 텍스트 뒤에 커서를 둔 뒤 Enter로 분리한다. 이미지가 있는 본문에서 전체 텍스트 선택은 문단 경계를 잘못 선택할 수 있다.
7. 재열람 후 이미지 로드와 실제 표시 크기를 확인한다. DOM 검증에서 `img[src]`만 세며 ProseMirror 구분용 이미지와 공동 편집 커서 위젯을 내용으로 세지 않는다.

대체 업로드는 미디어 삽입 → 로컬 이미지 → Upload Image 창 → 파일 선택 순서다. 메뉴 클릭은 OS 파일 선택을 열지 않는다. 파일 선택기 대기가 반복 실패하면 이미 검증된 HTML 붙여넣기를 사용한다. 과거 파일 URL 허용·Chrome 재시작 후 성공 이력이 있으나 모든 실패 원인을 권한 문제로 단정하지 않는다. 사용자에게 이미 완료한 설정을 근거 없이 다시 요구하지 않는다.

## 표·블릿·옛한글

- 표는 행·열·셀 내용을 먼저 확인하고 열 경계선에 마우스를 놓아 드래그한다. 열 너비 때문에 표를 삭제·재생성하지 않는다. HTML의 열 비율은 유지되지 않은 사례가 있다.
- 빈 셀의 문단을 클릭하기 어려우면 셀 자체를 선택하고 실제 커서를 확인한다. 조합 문자가 있는 표는 셀 단위로 입력·대조한다.
- 블릿은 원문의 채움/빈 원을 구분한다. 36번은 빈 원(circle) 4개였다.
- 옛한글은 문자표 → 문자 선택 → 옛한글 자모, 또는 음절 조합 → 초성·중성·종성 → 추가 → 적용을 사용한다. 지원되는 선택 입력란에서 복합 자모 문자열을 적용한 사례도 있다. PDF 추출의 PUA/누락 글자를 그대로 입력하지 않는다.
- 화면 형태와 저장 후 글자 보존을 함께 확인한다. 코드포인트 검사는 보조 수단이며 형태 대조를 대신하지 않는다.


## 대화체·시·텍스트 표시

- 대화는 발화마다 별도 문단, 화자 이름은 굵게 표시한다. 원문의 강조·밑줄·참조기호를 보존한다.
- 여러 문단 선택 후 눈금자 조절은 마지막 활성 문단에만 적용된 사례가 있다. 문단 하나씩 클릭 → AX 상태 갱신 → 현재 눈금자 위치 확인 → 드래그 → 스타일·화면 확인 순서로 조절한다.
- 38번과 [44~45]에서 18pt 왼쪽 여백과 -18pt 첫 줄 내어쓰기를 검증했다. 붙여넣기에서 내어쓰기 스타일이 제거될 수 있다. 화면 배율·단 폭이 바뀌면 과거 픽셀 이동량을 재사용하지 않는다.
- 시의 `<br>`/Shift+Enter는 현재 CSS에서 숨겨진다. 행마다 별도 문단을 사용한다. 실제 [22~26] 지문의 두 시를 18행·27행으로 입력하고 저장 후 행 순서를 대조했다. 행 문단에는 `line-height:125%`, 작품 표제·작가 표기에는 별도 문단을 사용했다. 원문에 없는 연을 임의로 만들지 않는다. 여러 연이 있는 다른 작품은 원문 연 경계를 따로 확인한다.
- 텍스트 테두리는 선택 영역에 테두리 상자 도구, 점선 리더와 구간 대괄호는 각각의 메뉴를 사용한다. 원문의 참조 글자와 적용 범위를 대조한다. 창작 표본에서 보존을 확인했으며 모든 조합의 보존을 보장하지 않는다.


## 브라우저 제어 복구

- 메타데이터 입력은 3~5개씩 나누어 저장 결과를 확인한다. 11개를 한 호출로 처리하다 60초 제한으로 세션이 초기화된 사례가 있다. 기존 키·값을 다시 읽고 누락분만 입력해 복구했다.
- 문서 전환 직후 AX 상태가 반환돼도 실제 본문은 로딩 중일 수 있다. 목표 문서 제목·URL과 `.ProseMirror[role="textbox"]`의 표시를 확인한 후 내용 검사·입력을 시작한다.
- 추가한 답항 선두에 U+200B가 들어간 사례가 있다. 원본 대조 시 이 편집기용 선두 문자만 구분하며 원문의 공백·특수기호·조합 문자를 무차별 정규화하지 않는다.


탭 제어가 끊어지면 현재 브라우저 목록을 다시 확인한다. 동일 등록 URL을 제어 가능한 새 탭에 열어 이미 저장된 내용을 확인한 뒤 이어갈 수 있다. 생성 버튼을 다시 누르지 않는다. 새 탭을 연 사실은 미저장 내용 복구를 뜻하지 않는다. 미저장 초안·기존 ID를 비교한다. 사용자 탭을 임의로 닫지 않는다.

## 완료 검증에서 추가한 입력·복구 규칙

- 제목 전환만 기다리지 말고 실제 발문 번호까지 확인한다. 문항 전환 직후 이전 본문이 잠시 남을 수 있다.
- 큰 이미지 여러 장을 한 번에 보내지 않는다. 572,263자 HTML(이미지 3장) 붙여넣기에서 Chrome 연결 종료가 두 번 재현됐다. 한 장씩 나눈 약 149,000~252,000자 입력은 성공했다. 이는 관찰값이며 고정 한도는 아니다.
- 이미지가 앞에 있는 본문에서 문자열 기반 선택 위치가 어긋난 사례가 있다. 대상 문단 클릭 → 실제 키보드 선택 → 선택 문자열 확인 → HTML 클립보드 쓰기 → Ctrl+V로 입력한다. 이미지 문단 중앙을 클릭하면 글자 대신 이미지가 선택될 수 있으므로 화면에서 커서를 확인한다.
- `.fill()`이나 붙여넣기를 호출한 것만으로 치환 성공을 판단하지 않는다. 임시 표지가 남거나 앞 문장이 합쳐지면 즉시 Undo하고 선택 범위를 다시 잡는다. 새로 작성한 문서 전체를 교체할 때도 Ctrl+A의 첫·끝 텍스트를 확인한다.
- 일반 지문은 편집기에서 확인한 `data-qti-viewbox` 구조를 HTML 클립보드로 입력해도 헤더 없는 네이티브 보기박스로 보존됐다. 직접 DOM 변경이나 내부 저장 API 호출은 사용하지 않는다.
- [40~43]은 물리 18쪽의 (가), 18쪽의 (나) 앞부분, 19쪽의 (나) 뒷부분 순서로 입력했다. 매체 화면은 원본 이미지로 보존하며 이미지 안의 글자는 개별 편집 대상이 아니다. 본문 텍스트 지문은 편집 가능한 문단으로 입력한다.
- 저장 실패와 저장 중은 완료가 아니다. 검증용 R01에서 저장 요청 차단 → ‘저장 실패’ → 탭 종료 → 같은 ID 재열기를 확인했다. 본문 B는 보존됐으므로 이를 ‘손실된 데이터의 자동 복원’이라고 부르지 않는다. 로컬 초안과 실제 재열기 내용을 비교한다.
- 저장 지연 검증에서는 ‘저장 중...’을 관찰하고 요청을 재개한 뒤 ‘저장됨’과 재열기를 확인했다. 장애 주입은 검증용 탭·문서에만 한정하고 종료 후 모든 차단·지연을 해제한다.
