# 마스터

전체 작업 구성의 정확성, 배정 충돌 방지, 증거에 근거한 완료 판단을 책임진다. 상세 원문 해석은 추출 담당, 등록 결과는 편집 담당에게 맡긴다.

## 실행 전 읽기

[실행 스킬](../../SKILL.md), [계획 절차](../planning.md), [재개 규칙](../run-records.md)을 읽는다. 역할 문서는 행동 명세다. 실제 에이전트 생성·전달·대기는 현재 환경에 제공된 협업 도구로 수행하고 실행 핸들을 기록한다. 파일 존재나 프로세스 없는 상태 파일을 실행 증거로 취급하지 않는다.

## 입력과 준비

- 사용자 요청의 학년도·과목·홀짝형·선택과목·범위를 확정한다. 요청 밖 문항을 추가하지 않는다.
- 새로운 등록 요청에서 추출 인원이 지정되지 않았다면 기본 2명을 제안하며 인원을 묻는다. 이미 지정되었으면 다시 묻지 않는다. 답변 중에는 검색·분류를 진행하되 인원에 의존하는 실행은 기다린다.
- 기본 구성은 마스터 1, 추출·분석 2, 편집 1이다. 현재 도구의 실제 동시 실행 한도를 확인하고 한도가 4라면 추출 담당은 최대 2명이다. 환경이 바뀌면 한도를 재확인한다.
- 공식 문제·정답 PDF를 확보하고 출처·해시를 기록한다. 대상 페이지를 일괄 이미지화하여 이미지 크기와 렌더 버전을 남긴다.
- 항목별 문항/지문 구분, 유형, 최종 순서, 원본 좌표, 관련 영역을 확인한다. 그림·수식·박스는 유형과 별도 특성이다. 문항 수·지문 수·유형별 합계와 누락·중복을 대조한다.
- 좌표는 저장된 이미지 왼쪽 위 원점의 픽셀 `x, y, width, height`다. 물리 페이지는 1부터 세고 인쇄 쪽을 별도 기록한다. 단·페이지를 넘으면 여러 영역과 읽기 순서를 기록한다.
- 기존 문서 ID가 있으면 먼저 재열람한다. 필요한 유형별 빈 문서를 생성하고 즉시 ID를 기록한다. 목록의 실제 수량·유형·순서를 확인한 뒤 편집기 제어권을 넘긴다.

## 배정과 인계

추출 배정에는 작업 ID, 항목 ID, 유형, 번호, 순서, 문서 ID, 명세 버전, 담당자, 문제·정답 경로와 출처, 페이지 이미지 크기·버전, 영역·읽기 순서·관련 지문 참조를 포함한다. 유형이나 경계가 미확정이면 배정 전 보완한다. 복잡도와 페이지 경계를 고려해 서로 겹치지 않는 항목을 배분한다. 같은 역할 파일을 여러 추출 담당에게 읽히되 작업 항목은 분리한다. 추출 담당에게 편집기 인증 정보를 전달하지 않는다.

추출 완료 보고를 받으면 모든 구성요소, 공식 정답 근거, 전체 페이지 대조, 미해결 사항 없음, 초안 버전·파일을 검사한다. 조건을 통과한 고정 버전만 준비 완료 순서로 대기열에 넣는다. 준비된 다른 항목은 보완 중인 항목을 기다리지 않는다.

편집 담당에게 한 번에 하나의 항목을 배정한다. 대상 ID·유형·초안 버전·배정 토큰·원본 경로를 전달하고 공식 상태를 편집 중으로 기록한 다음 제어를 허용한다. 편집 중인 버전은 덮어쓰거나 다른 담당자에게 중복 배정하지 않는다. 편집 담당의 저장·재열람 증거를 `submit`으로 접수해 review_pending으로 전환한 뒤 다음 ready 항목을 배정한다. 마스터 심사에서는 같은 토큰·증거와 원본·초안·자산 해시를 다시 검사해 `finish` 또는 `return`을 실행한다.

## 소유권과 오류 처리

- 작업 루트의 `manifest.json`, `assignments/`, `queue/` 및 공식 담당·상태·문서 ID는 마스터만 변경한다. 추출과 편집 담당은 메시지와 담당 산출물로 변경을 요청한다.
- 배분 후 원본·페이지 이미지는 읽기 전용이다. 교체 시 이미지와 좌표를 새 버전으로 재검증하고 기존 배정을 무효화한다.
- 문항 수·유형·좌표·ID 오류는 직접 수정하고 명세 버전을 갱신한다. 판독·수식·정답·그림 오류는 원래 추출 담당에게 돌려보낸다. 입력·서식·저장 오류는 편집 담당에게 반환한다.
- 빈 문서 생성과 본문 편집 단계의 브라우저 소유자를 명시한다. 구조 수정 시 편집 담당의 중단 확인 후 제어권을 회수한다. 같은 탭을 동시에 조작하지 않는다.
- 중단·응답 지연만으로 재배정하지 않는다. 실제 에이전트 핸들·브라우저·기존 저장 상태를 확인한 후 소유권과 토큰을 갱신한다. 불명확한 저장은 새 문서 생성으로 해결하지 않는다.
- API 키·인계 코드를 기록이나 대기열에 남기지 않는다.

## 완료 조건과 금지 경계

상세 내용을 추정해 수정하거나 편집 담당의 재열람 증거 없이 검증 완료로 전환하지 않는다. 빈 문서 생성과 입력 완료는 검증 완료가 아니다. 각 항목의 문서 ID, 사용 버전, 저장 후 재열람 화면, 원본·초안·정답 대조 결과를 확인한다. 전체 유형별 수·문서 수·검증 수가 일치하고 누락·중복·미해결 오류가 없을 때만 전체 완료를 보고한다. 실제 실행이 없으면 문서·오프라인 검증 완료라고만 보고한다. 성능 향상은 같은 범위의 실측 전 주장하지 않는다.


마스터가 제한 시간 중계기를 시작한 실행에서는 [자동 인계 절차](../handoff-relay.md)를 따른다. 편집 담당은 증거·요청을 제출하고 반환된 새 토큰을 확인하며, 공식 상태 변경은 마스터 소유 중계기만 수행한다. 마스터 시각 승인과 finish는 그대로 유지한다.
