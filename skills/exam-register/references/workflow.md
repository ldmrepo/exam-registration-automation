# 실행 절차

배포판 실행 절차. 실행 기록은 connector.py status가 반환하는 사용자 runs 경로에 보관한다.

## 범위

공식 시험지 검색 → PDF 브라우저 표시·시각 판독 → 지문·문항별 편집기 입력 → 원본 대조 → 저장·재열람까지 수행한다. 지문과 문항은 각각 독립 문서다. 공통 지문과 여러 문항의 앱 내 연결, 출력·내보내기는 제외한다. Codex가 스킬을 따라 수행하는 방식이며 별도 무인 실행기나 일정 자동 실행은 이번 완료 범위에 포함하지 않는다.

## 1. 요청과 기존 작업 확인

- 학년도, 시험 종류·회차, 영역, 선택과목, 홀짝형, 지문/문항 범위, 대상 폴더를 요청과 기존 기록에서 확인한다. 학년도와 시행 연도는 다르다.
- 모호한 정보가 실제 시험 선택을 바꾸는 경우에만 질문한다. 독립적으로 가능한 검색·기록 확인은 먼저 한다.
- 사용자 `runs/`의 명세를 조회한다. [재개 기록 규칙](run-records.md)에 따라 완료·기존 미검증·새 작업을 구분한다. 재실행이라고 전체를 새로 생성하지 않는다.

## 2. 공식 검색과 원본 식별

- [평가원 게시판](https://www.suneung.re.kr/boardCnts/list.do?boardID=1500234&m=0403&s=suneung&searchStr=)에서 요청한 시험·과목을 찾는다. 검색어만 믿지 말고 게시물과 첨부 제목을 확인한다.
- 문제지와 정답표의 시험·과목·선택과목·홀짝형을 대조한다. URL, 게시물 번호, PDF 파일명과 로컬 원본을 기록한다. 새 파일에는 SHA-256도 남겨 같은 이름의 다른 파일을 구분한다.
- 이미 확보한 원본은 재사용할 수 있다. 새로 받은 파일과 기존 파일이 다른 경우 이전 기록을 덮어쓰지 않고 버전을 구분한다.

## 3. 시각 판독과 입력 초안

- PDF를 브라우저에 열어 실제 페이지를 확대해 읽는다. 필요하면 원본을 렌더·잘라 이미지로 보존하고 잘림 여부를 눈으로 확인한다.
- 물리 페이지와 인쇄 쪽을 각각 기록한다. 2026 국어 PDF는 홀수형 1~20, 짝수형 21~40이며 선택과목마다 35~45번이 반복된다. 이 배치를 다른 시험지에 자동 적용하지 않는다.
- 문항 번호·발문·보기·답항·그림·수식·참조기호·배점을 구분한다. 지문은 원문의 시작 안내와 끝을 확인하고 단/페이지를 넘더라도 읽기 순서대로 잇는다. 인접 문항의 답항이나 페이지 머리말을 섞지 않는다.
- 추출 텍스트는 입력 보조일 뿐이다. 옛한글, 수식, 도표는 시각 대조한다. 정답표에 없는 답을 추론해서 공식 정답으로 입력하지 않는다.

## 4. 편집기 입력

- 실제 대상 폴더를 확인한 뒤 문서를 생성한다. 새 폴더 생성은 첫 문서를 함께 만들 수 있으므로 중복 생성을 주의한다. 생성 ID를 알게 되면 내용 완성 전에 기록한다.
- 지문: 일반 문서에 안내 발문을 두고, 헤더 없는 보기박스 안에 지문을 입력한다.
- 문항: 별도 QTI 문서에 발문·보기·답항·공식 정답·배점을 입력한다. 제목에 시험 식별과 문항 번호를 포함한다.
- [편집 기능 지침](editor-playbook.md)에 따라 해당 요소를 입력한다. 본문·개별 답항·표 셀처럼 작은 범위에서 작업하고 삽입 위치를 확인한다.
- 지원되는 정보 탭에는 출처·학년도·과목·선택과목·유형·번호·job_key를 키 기준으로 기록한다. 일반 문서는 임의 메타데이터가 없으므로 로컬 명세에 대응 관계를 남긴다.

## 5. 저장 전 대조와 재열람

- 원본 기준으로 발문, 답항 순서·개수, 기호·수식·표, 그림 위치·비율, 옛한글, 문단 순서를 대조한다. 임시 단어와 불필요한 빈 문단을 제거한다.
- 저장 완료 표시를 확인하고 다른 문서로 이동한 뒤 같은 문서를 다시 연다. 수정 중 화면의 정상 표시만으로 저장 성공을 판단하지 않는다.
- 이미지 실제 로드, 정렬·크기, 수식 렌더링, 답항·정답, 표·특수문자 보존을 다시 확인한다. UI 미리보기와 본문이 다르면 실제 편집 본문을 기준으로 확인한다.
- 모두 통과하면 `verified`로 기록한다. 실패는 기존 ID를 유지하며 보류 사유와 다음 조작을 기록한다.

## 6. 재실행과 종료

범위의 모든 항목이 완료·기존 확인·보류 중 하나로 설명되어야 한다. 단순히 최대 문항 번호만 기록하지 않는다. 이미 완료된 항목은 실제 문서 일치 확인 후 생성을 생략한다. 기존 문서가 없거나 사용자 수정과 충돌하면 [재개 기록 규칙](run-records.md)에 따라 처리한다.

보고할 내용: 새 등록 수, 기존 확인 수, 보류 수, 문서 링크, 남은 범위. 새 실행 검증과 이전 실행 근거를 구분한다.

## 현재 검증 수준

수학 1~5·7·14번 7문항과 국어 언매 선택과목 전체 35~45번 11문항을 실제 등록·재열람했다. 국어 지문은 [35~36], [40~43], [44~45], [22~26] 네 개다. [40~43]은 물리 18→19쪽 연결, [22~26]은 두 시의 18행·27행과 산문 3문단을 대조했다. 창작 형식 표본과 복구용 R01은 공식 등록 수에 합산하지 않는다.

부분 저장 이어쓰기·메타데이터 제어 중단·큰 이미지 붙여넣기 연결 종료·저장 실패·저장 지연·탭 종료 후 같은 ID 재열기를 시험했다. 저장 실패 중 본문이 보존된 결과와 실제 손실 복원은 구분한다. 검증 범위가 국어 전체 45문항이나 모든 시험 유형의 정확도를 보장하지 않는다. 이 수치는 이전 개발 환경의 검증 기록이며 배포판에는 그 개인 실행 자료를 포함하지 않는다.
